# v4.5 client engine audit

## Research (honest scope)
- Local skills in `.agents/skills/` (improve-ui, impeccable, taste-skill, ui-ux-pro-max, better-ui/layout/motion, audit-ai-design-slop, agent-reach, rea) exist in the repo; `rea` and `agent-reach` are not installed as binaries in this session (`which rea` empty), so no tool runs were made with them. `npx ui-skills list` was not run.
- Web/GitHub research on Polyfrost OneClient/OneConfig, ModMenu and Sodium was **not** performed in this session. No third-party code was read or copied (AGENTS.md: reference projects are GPL, study behaviour only). The design below comes from the repo's own v4.4 work and the Minecraft 1.21.11 Mojang-mapped API.

## What the code is (differs from the brief's assumptions)
- Package `dev.luminos.client`, Mojang mappings, Minecraft 1.21.11 (not 1.21.4, not Yarn): `KeyboardHandler.keyPress`, `GuiGraphics`, `Minecraft.setScreen`.
- Layout and hit-testing live in `src/shared` (`MainMenuView`, `ModPanelView`, `HudEditor`) behind the `Gfx` interface; the `Screen` classes in `src/legacy` are thin delegates. That is what lets the same code paint in the game and in an offscreen Java2D image.
- Title screen: `MinecraftClientMixin.setScreen` (`@ModifyVariable`) + `TitleScreenGuardMixin.init` fallback; `renderBackground` is a no-op in both Luminos screens.
- Right Ctrl: `KeyboardMixin.keyPress` at HEAD + a rising-edge GLFW poll in `MinecraftClientMixin.runTick`; `QuickPanelToggle` debounces; the open/close rule is the pure `PanelRouting.route`.

## v4.5 changes
- Startup screen: seven rows in one left column with keyboard navigation (Up/Down/Tab/Enter, H), brand pill with live engine badge pill, Right Ctrl hint pill.
- Quick panel: tabs renamed All/HUD/Render/World/PvP/Movement/FPS; no vanilla widgets; test hooks for named rectangles.
- Headless suite `ClientScreenRenderAndInputTest` (9 tests) and `./gradlew testAndRenderScreens`.

## Not done / deliberately different
- No colour swatches or opacity slider in the drawer: modules have no accent/opacity setting to bind them to, and a control that changes nothing would be fake.
- The "0ms HUD overhead" claim is not shown: it is not measured.
- "3D Capes & Cosmetics" opens the existing `LuminosCosmeticsScreen`, not the quick panel.
- Tests do not instantiate the `Screen` subclasses or run the Mixins (needs a live Minecraft window). Nothing here was launched in a real game.
